# T4 — Data Pipeline and Persistence

## Goal

Make the tray, egg result, API, CSV, database, and dashboard data consistent.

## Status

Implementation complete and migration applied. Physical 0–5 tray acceptance is
still open under T7.

## Decisions

- `predictions` is the tray-level record. A separate `trays` table is not used
  because one prediction row already owns one tray image, `tray_id`, operator,
  capture time, aggregate counts, and inference metadata.
- `detection_boxes` stores one row per detected egg.
- Per-tray model versions, thresholds, calibration version, capacity status,
  and duplicate-removal count live in `predictions.inference_metadata`.
- Over-capacity trays keep all detections and are marked for review; counts are
  never silently capped.
