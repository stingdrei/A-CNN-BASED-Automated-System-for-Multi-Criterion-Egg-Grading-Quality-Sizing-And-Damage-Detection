# T2 — Grading Logic and API Contract

## Goal

Make size, weight, damage, cleanliness, and per-egg output behavior conform to
the locked project specification.

## Tasks

- [ ] Replace old size bins with:
  - Small: `< 53 mm`
  - Medium: `53–60 mm`
  - Large: `> 60 mm`
- [ ] Replace diameter-cubed weight estimation with:
  `W = k × L × B²`.
- [ ] Fit `k` from known-weight calibration data before production use.
- [ ] Extract major axis `L` and minor axis `B` from validated egg geometry.
- [ ] Add cleanliness status and confidence to inference.
- [ ] Implement grading rules:

```text
Damaged -> Reject
Stained -> Reject
Clean + Large -> A
Clean + Medium -> B
Clean + Small -> C
Unknown/invalid -> N/A
```

- [ ] Return one per-egg object with:
  `egg_id`, `grade`, `size`, `weight_g`, `damage_status`,
  `cleanliness_status`, and nested confidence fields.
- [ ] Keep API, CSV, database, and frontend field names identical.
- [ ] Resolve the grade/class terminology choice and apply it consistently.
- [ ] Update `references/grading-rules.md`.

## Verification

Test all combinations of damage, cleanliness, and size, including invalid and
low-confidence inputs. No damaged or stained egg may receive A, B, or C.
