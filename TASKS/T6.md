# T6 — Cleanup, Consistency, and Release

## Goal

Remove stale behavior, align all interfaces, and prepare a versioned release.

## Tasks

- [ ] Use one fixed confidence threshold consistently across code, tests,
  frontend, and documentation. Current locked target: `0.75`.
- [ ] Choose either `Grade A/B/C` or `Class A/B/C`; use one terminology
  everywhere.
- [ ] Update `egg-grading-system.skill` to reflect FastAPI, PNS/BAFS size
  mapping, and stained-egg rejection.
- [ ] Remove stale tracking comments and video-oriented instructions.
- [ ] Update frontend types for:
  - `egg_id`
  - `size`
  - `damage_status`
  - `cleanliness_status`
  - nested confidence fields
  - calibrated geometry and weight
- [ ] Update result, history, dashboard, and upload pages.
- [ ] Remove incompatible legacy grade values such as `AA` if not supported.
- [ ] Add API, model, grading, and frontend tests.
- [ ] Check documentation against actual commands and paths.
- [ ] Record checkpoint hashes and model versions.
- [ ] Run the complete release validation suite.
- [ ] Commit the final model reports and source manifests, excluding secrets
  and unsupported large binaries.

## Release checklist

- [ ] Backend starts successfully.
- [ ] Frontend builds successfully.
- [ ] All targeted tests pass.
- [ ] A 0–5 egg tray is handled correctly.
- [ ] Damaged and stained eggs are rejected.
- [ ] Unknown or low-confidence inputs do not receive a passing grade.
- [ ] API, CSV, database, and frontend outputs agree.
- [ ] Final test reports are present and reproducible.
